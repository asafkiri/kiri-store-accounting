# החשבונות של החנות

מערכת בעברית וב־RTL לחנות המשפחתית: רואים חשבוניות שלא שולמו, משלמים ומסמנים כשולם. רישום קופה ורב־קו נפרד. אין הנהלת חשבונות כפולה או יתרת ספק מתגלגלת.

**כתובת הפריסה המיועדת:** https://kiri-store-accounting.web.app

**להשלמת ההפעלה בתשתית הקיימת:** [מדריך מדויק, צעד־אחר־צעד](docs/SETUP.md). אין להסיק מהימצאות הקוד שהפריסה, SMS או קריאה אמיתית ל־Luna כבר אומתו.

## מה קיים

- חשבוניות פתוחות בראש המסך; הוספה ידנית מלאה, עריכה, חיפוש, סינון, מחיקה לאחר אישור.
- ספקים: הוספה, עריכה, חיפוש, פעיל/לא פעיל, סכום חשבוניות פתוחות וצפייה בהיסטוריה.
- תשלום במזומן, צ׳ק, העברה, כרטיס או אחר. יום מסירת הצ׳ק נשמר כ־paymentDate; מועד פירעון בנפרד.
- קופה ורב־קו: שתי תיבות עצמאיות לכל תאריך, היסטוריה וייצוא. סכום חסר שונה מאפס.
- דוחות לפי חודש/טווח, ספק, מצב ואמצעי תשלום; סכומים לפני מע״מ, מע״מ, כולל וסופי.
- סכום מע״מ חסר נשאר חסר ומסומן בסיכום; אין חישוב אוטומטי של 18%.
- צילום/בחירת תמונות או PDF, עד 8 עמודים, preview וצילום מחדש. סקירה של ערכי ה־AI מול הערכים שיישמרו, ורק אז שמירה ידנית.
- כלי אופציונלי להשוואת דוח רואה חשבון; אינו משנה חשבוניות.
- CSV חודשי/מסונן, JSON של הנתונים, הדפסה או שמירת הדוח כ־PDF דרך הדפדפן.
- טיוטות מוצפנות מקומית ב־IndexedDB, כולל בקשות שמירה ממתינות; שמירה בשרת מוצגת רק אחרי אישורו.
- מניעת כתיבה כפולה ודריסת גרסה ממכשיר אחר; טיוטה שהתנגשה נשמרת לעיון.

## מבנה וארכיטקטורה

ממשק JavaScript מודולרי, CSS מותאם לטלפון, esbuild לאריזה, Firebase SDK להתחברות בלבד. אין ספריית UI כבדה. השרת נמצא בריפו [kiri-store-accounting-ai-scan](https://github.com/asafkiri/kiri-store-accounting-ai-scan).

`Browser → Firebase Phone Auth → Bearer Firebase ID token → /api/v1 → Cloud Run → Admin SDK → Firestore / Storage`

Firebase Hosting מפנה את `/api/**` לשירות הקיים באזור `us-east1`, ולכן אין צורך להטמיע URL של שרת ב־frontend ואין CORS wildcard. אין GitHub Pages או אירוח נוסף.

הדפדפן אינו פונה ל־Firestore, ל־Storage או ל־OpenAI ישירות. `firestore.rules` ו־`storage.rules` מגדירים `allow read, write: if false` לכל הנתיבים. בדיקת מספר הטלפון/UID מתבצעת בשרת; המספר אינו בקוד הציבורי. Phone Auth עצמו אינו מגביל בקשת OTP למספר מורשה בלבד.

| קובץ / תיקייה | אחריות |
|---|---|
| `src/auth.js` | SMS והתחברות מתמשכת |
| `src/api.js` | token, timeout, בקשות ושגיאות ללא retry סמוי |
| `src/drafts.js` | טיוטות AES-GCM לפי UID במכשיר |
| `src/forms.js` | חשבונית, ספק, תשלום וסגירה יומית |
| `src/scan.js` | קבצים, סקירה והשוואת דוח |
| `src/views.js`, `src/styles.css` | מסכים ועיצוב RTL responsive |
| `src/format.js`, `src/export.js` | אגורות, תאריכים עסקיים וייצוא |
| `src/app.js` | ניווט, טעינה וסנכרון |
| `src/agent-tools.js` | הרחבה אופציונלית לקריאת סיכום מורשה בדפדפן תומך WebMCP |

כל האוספים נמצאים תחת `stores/family`. סכומים הם integer agorot; תאריכים עסקיים הם מחרוזות `YYYY-MM-DD`. הסכמה המלאה וה־API מתועדים ב־[README של השרת](https://github.com/asafkiri/kiri-store-accounting-ai-scan#readme).

## התקנה, build ובדיקות

Node.js 22 ומעלה.

```sh
npm ci
npm test
npm run build
```

תוצרי Firebase Hosting נמצאים ב־`dist/`. כל התלויות נעולות ב־`package-lock.json`.

`npm test` כולל חישובי אגורות, תאריכים בישראל, פילטרים, CSV, ניסיונות שמירה אחרי ניתוק, טיוטות מוצפנות לאחר reload ובדיקות טפסים ב־DOM מבודד. הבדיקות אינן שולחות SMS אמיתי ואינן מפעילות AI בתשלום. יש להריץ גם את בדיקת הקצה בטלפון לאחר פריסה.

```sh
npm run dev
```

שרת הקבצים המקומי זמין ב־http://127.0.0.1:4173 לאחר build. זו תצוגה סטטית בלבד: Firebase Auth דורש את ה־reserved URL שמספק Firebase Hosting. לבדיקה מלאה מקומית השתמש ב־Firebase Hosting emulator עם הגדרת web app בפרויקט, ובאמולטורי Auth/Firestore/Storage עבור נתוני בדיקה לפי תיעוד השרת. שרת סטטי רגיל אינו יוצר תשתית או עוקף התחברות.

## תצורת Firebase ופריסה

אין `.env` ל־frontend ואין צורך להעתיק מפתחות שרת. האפליקציה קוראת את `/__/firebase/init.json` ש־Firebase Hosting מספק עבור ה־Web App בפרויקט. זהו config ציבורי של Firebase; הרשאות המידע נקבעות בשרת וב־Rules. אם עדיין אין Web App רשום, הוסף Web App בתוך הפרויקט הקיים לפי מדריך ההפעלה.

```sh
npm ci
npm test
npm run build
npx firebase-tools@14.16.0 deploy --project kiri-store-accounting --only hosting,firestore:rules,storage
```

הפקודה דורשת חשבון Google מורשה. כללי Firestore/Storage נשארים חסומים. אין פריסה אוטומטית ל־Firebase על כל commit; GitHub Actions בודק build/tests, והפריסה מתבצעת עם CLI מורשה. אין צורך לחשוף service-account key ב־GitHub.

## אמינות, פרטיות ומגבלות ידועות

- כל טופס מקבל ID קבוע לפני השליחה. בקשה שנקטעה נשמרת כבקשה ממתינה עם אותו mutationId; לחיצה חוזרת משלימה אותה במקום לייצר פעולה חדשה.
- פרטי טיוטה נשמרים במכשיר בלבד; רשומה שנשמרה בשרת זמינה במכשיר אחר. הצפנת IndexedDB מצמצמת שמירת טקסט גלוי, אך אינה מגינה ממכשיר פרוץ או XSS באותו origin. יציאה מוחקת את הטיוטות המקומיות.
- refresh בזמן כתיבה שטרם הסתיימה יכול להציג אזהרת דפדפן קצרה. אם המכשיר אינו מאפשר שמירת טיוטות, השמירה נעצרת במקום לשלוח בקשה שאין אפשרות לשחזר.
- אין service worker ואין cache של תגובות עסקיות; הרשומות שנטענו נשמרות בזיכרון בלבד. manifest מאפשר הוספה למסך הבית, אבל פתיחה חדשה ללא רשת אינה מובטחת. אפשר להמשיך למלא טופס שכבר פתוח בניתוק ולשמור כשיש רשת.
- אין polling. רענון ידני, חזרה לאפליקציה לאחר דקה או חזרת חיבור מבקשים רק שינויים מאז הגרסה האחרונה. snapshot ראשון מכיל את נתוני החנות; אין כיום מנוע חיפוש חיצוני.
- CSV/JSON כוללים מידע עסקי ולכן יש לשמור את ההורדות במקום מתאים. גיבוי JSON כולל נתונים ומטא־נתונים של קבצים, לא את התמונות/PDF עצמם. אין ייבוא שיכול לדרוס נתונים בשקט.
- מע״מ מסוכם לפי סכומים שהוזנו, כולל סימנים של זיכויים; ניכוי ידני אינו משנה את המע״מ המודפס. הדוח אינו דיווח רשמי.
- השוואת רואה חשבון כרגע לפי חודש שנבחר ועד 200 שורות דוח. התאמה מלאה דורשת ספק+מספר+תאריך+כולל+מע״מ, אחרת מוצג צורך בבדיקה; אין קביעה שרואה החשבון טעה.
- התמיכה האופציונלית ב־WebMCP נבדקת באמצעות registry מדומה. לא אומתה כאן בדפדפן עם הממשק המוצע הזה.
